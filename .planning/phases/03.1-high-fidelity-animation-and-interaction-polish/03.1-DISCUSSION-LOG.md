## Theme motion signatures

### Resting motion intensity

| Option | Description | Selected |
|--------|-------------|----------|
| Barely perceptible | Slow micro-motion visible only when watched; safest for readability but may still feel mostly static. | |
| Clear but restrained | Each theme has an obvious signature at a calm cadence, while text and state cues remain visually dominant. | ✓ |
| Showcase motion | Continuous, attention-grabbing movement; higher distraction and rendering pressure. | |

**User's choice:** Clear but restrained.
**Notes:** The user explicitly does not want animation everywhere. Improve animation that already exists; add only less-distracting motion where it earns its place.

### Theme differentiation

| Option | Description | Selected |
|--------|-------------|----------|
| Distinct metaphors | Signal Edge rail activity, Ledger typographic/row cues, Beacon field breathing, and Instrument gauge or sweep behavior. | ✓ |
| Shared motion grammar | The same fades, pulses, and timings everywhere with theme-specific styling. | |
| Animate selected themes | Some themes move while quieter themes remain static except for feedback. | |

**User's choice:** Distinct metaphors.
**Notes:** Preserve four genuinely different display languages.

### Animated visual layer

| Option | Description | Selected |
|--------|-------------|----------|
| Accents around stable content | Move rails, underlines, fields, ticks, or gauge markers while titles, state words, and primary glyphs remain fixed. | ✓ |
| Primary state forms | Allow glyphs, rings, and large state forms to pulse, rotate, or morph. | |
| Background field only | Keep every semantic mark fixed and animate low-contrast backgrounds only. | |

**User's choice:** Accents around stable content.
**Notes:** Some glyph motion is allowed when it fits the metaphor; a rotating ring was the user's example.

### Animated state set

| Option | Description | Selected |
|--------|-------------|----------|
| Attention states only | Blocked, unseen, and working may move; idle and settled stay still. | |
| All current occupied states | Every occupied tile has a subtle signature, with attention states amplified. | |
| Theme-specific state set | Each theme chooses animated and intentionally static states according to its own visual metaphor. | ✓ |

**User's choice:** Theme-specific state set.
**Notes:** Downstream work must inventory every relevant state rather than assume one global matrix.

## Transition choreography

### Ordinary live-data replacement

| Option | Description | Selected |
|--------|-------------|----------|
| Short semantic transition | Brief theme-specific reveal for ordinary changes; stale, offline, SYNC, and safety fences remain immediate. | ✓ |
| Immediate replacement | Complete-frame cuts for live data; animation reserved for ambient and interaction feedback. | |
| Animate every update | Visibly transition all changes, including frequent refreshes. | |

**User's choice:** Short semantic transition.
**Notes:** Truth and safety changes do not wait for decorative motion.

### Cross-theme consistency

| Option | Description | Selected |
|--------|-------------|----------|
| Shared timing, distinct visuals | One bounded duration and interruption rule; rail, row, field, or gauge-specific choreography. | ✓ |
| One shared transition | The same wipe or fade in every theme. | |
| Fully theme-specific | Each theme chooses both timing and choreography. | |

**User's choice:** Shared timing, distinct visuals.
**Notes:** Responsiveness must feel consistent even while theme identity remains visible.

### Encoder-menu movement

| Option | Description | Selected |
|--------|-------------|----------|
| Spatial slide and scroll | Rows move with encoder direction; detail pages slide in/out; brightness updates continuously. | ✓ |
| Fade between surfaces | Crossfade root and detail content. | |
| Mostly immediate | Animate only menu open/close; cursor, page, and brightness changes cut immediately. | |

**User's choice:** Spatial slide and scroll.
**Notes:** The user later clarified that menu feedback must remain snappy. Animation may follow interaction but cannot prevent or postpone the immediate response.

### Stale/offline/SYNC recovery

| Option | Description | Selected |
|--------|-------------|----------|
| Immediate fence, staged recovery | Failure fences appear immediately; recovery uses a short per-panel theme-specific reveal after safe commit. | ✓ |
| Global veil then cut | Keep all panels under SYNC and replace the full surface without a flourish after safe commit. | |
| Recovery flourish | Run a visible all-panel reconnection sequence after commit before settling into live state. | |

**User's choice:** Immediate fence, staged recovery.
**Notes:** Existing binding fencing and safe commit semantics remain unchanged.

## Focus and encoder feedback

### Immediate keypress response

| Option | Description | Selected |
|--------|-------------|----------|
| Immediate press impulse | One-frame or very short tactile compression/flash, then the pending cue. | ✓ |
| Pending cue only | Switch directly to the existing pending state. | |
| Hold pressed appearance | Keep the tile depressed until success or failure. | |

**User's choice:** Immediate press impulse.
**Notes:** The impulse confirms physical input only; it must not imply focus success.

### Pending interval

| Option | Description | Selected |
|--------|-------------|----------|
| Localized continuous motion | A small theme-specific spinner, sweep, or traveling accent while identity and state remain fixed. | ✓ |
| Calm stepped pulse | A slower two- or three-frame pulse. | |
| Static pending badge | Immediate `PENDING` text and color only. | |

**User's choice:** Localized continuous motion.
**Notes:** Waiting should feel alive without moving the content the user is identifying.

### Terminal focus results

| Option | Description | Selected |
|--------|-------------|----------|
| Brief success, durable failure | Short success flourish around the existing ~800 ms hold; failure-family results use the longer bounded hold. | ✓ |
| All results brief | Clear every result quickly. | |
| Persist all results | Keep success and failure until the next snapshot or press. | |

**User's choice:** Brief success, durable failure.
**Notes:** Preserve the distinction between reassuring success and errors that must not be missed.

### Encoder physical causality

| Option | Description | Selected |
|--------|-------------|----------|
| Direct physical causality | Every detent moves one row immediately; click responds immediately; confirmation settles; cancel/timeout reverses preview. | ✓ |
| Minimal highlight changes | Immediate cursor/value changes with little animation. | |
| Momentum and easing | Inertial scrolling and stronger eased motion. | |

**User's choice:** Direct physical causality.
**Notes:** Do not add momentum or let easing make the detented encoder feel imprecise.

## LED/display coordination

### Synchronization strength

| Option | Description | Selected |
|--------|-------------|----------|
| Semantic synchronization | Synchronize blocked, press, pending, success/failure, menu, and health moments; decorative ambient accents may differ. | ✓ |
| Full lockstep | Every display animation phase drives the matching LED phase. | |
| Mostly independent | Displays and LEDs share state but animate on separate rhythms. | |

**User's choice:** Semantic synchronization.
**Notes:** Coordination should communicate meaning rather than mechanically mirror every frame.

### Resting LED motion

| Option | Description | Selected |
|--------|-------------|----------|
| Preserve grammar restraint | Improve existing pulses and traveling cues without universal breathing; intentional dark/static behavior remains valid. | ✓ |
| Subtle life everywhere | Give every grammar a low-level resting animation. | |
| Semantic motion only | Permit LED motion only for attention, feedback, health, or menu events. | |

**User's choice:** Preserve grammar restraint.
**Notes:** The user wants more state-to-state blending where it fits each grammar, not a shared effect imposed everywhere.

### LED state blending

| Option | Description | Selected |
|--------|-------------|----------|
| Blend ordinary, cut urgent | Blend normal state, menu, and successful-focus changes; assert blocked, health fences, rejection, failure, and uncertainty immediately. | ✓ |
| Blend every change | Smooth interpolation for all changes, including errors and fences. | |
| Blend resting states only | Only ordinary resting-state changes interpolate; interaction and health cues cut immediately. | |

**User's choice:** Blend ordinary, cut urgent.
**Notes:** No ambiguous blend may delay an urgent semantic cue.

### Visual acceptance coverage

| Option | Description | Selected |
|--------|-------------|----------|
| Exhaustive visual matrix | Every relevant tile, fence, feedback, SYNC, Codex, and menu scene in all themes; all 16 theme/LED combinations physically stressed. | ✓ |
| Full themes, sampled combinations | All scenes in every theme; representative theme/LED pairings physically stressed. | |
| Curated critical paths | Highest-risk scenes and one preferred combination per theme. | |

**User's choice:** Exhaustive visual matrix.
**Notes:** Physical flows include normal refresh, rapid interaction, live updates, stale/offline transitions, and reconnect/reset. Framebuffer and physical evidence cover different failure classes and are both required.
