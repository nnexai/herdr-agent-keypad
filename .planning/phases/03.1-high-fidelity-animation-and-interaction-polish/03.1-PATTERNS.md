## Pattern Assignments

### `firmware/src/ui/animation.h` (scheduler, periodic/event-driven)

**Analog:** the existing `AnimationScheduler` (same file, lines 5–95).

**Ownership and seam:** The scheduler decides *when* a bounded frame is due and the degradation level; it never draws, owns no host truth, and performs no allocation. `AgentProjection::tick()` remains the consumer that decides which complete panels to recompose. Extend this class rather than adding an animator in a theme or projection.

**Core contract** (lines 5–15, 21–41):

```cpp
// Every frame ... is recomposed and flushed as a complete frame ...
// the scheduler itself never draws and never allocates.
static constexpr uint32_t kBlockedPeriodUs = 1200000UL;
static constexpr uint32_t kBudgetPercent = 30;
enum class Level : uint8_t { Full = 0, Half, Static };
void observeFlushCost(uint32_t flush_us, uint32_t loop_window_us) {
  if (loop_window_us == 0) return;
  const uint32_t period = activePeriodUs();
  if (period == 0) return;
  const uint64_t duty = (static_cast<uint64_t>(flush_us) * 100U) / period;
  if (duty > kBudgetPercent) {
    level_ = level_ == Level::Full ? Level::Half : Level::Static;
  } else if (duty * 2 <= kBudgetPercent) {
    level_ = level_ == Level::Static ? Level::Half : Level::Full;
  }
}
```

**Blocked/event epoch** (lines 46–65): `blockedPhaseEpoch()` and `blockedPulseHigh(now_us)` are the shared display/LED reference. `blockedFrameDue()` emits only after crossing a half-period boundary. Preserve BLOCKED as the last animation to degrade; urgent source fences must bypass ambient scheduling, not wait for a pulse.

**Ambient cadence** (lines 67–87): a theme declares its natural period; Full uses that period, Half doubles it, and Static returns no ambient frames. New transition phases/progress should be bounded integer/time fields and reset on interruption. Keep phase arithmetic wrap-safe and deterministic so capture fixtures can sample Full, Half, and Static.

**Tests to copy:** `test_blocked_pulse_cadence_and_phase` and `test_ambient_cadence_degrades_under_budget_pressure` (`test/test_agent_projection/test_main.cpp:1229-1262`). Add phase-table assertions at this seam, not renderer timing sleeps.

**Avoid:** drawing from `AnimationScheduler`; per-frame `new`, `std::vector`, or timestamp-owned host semantics; using the current fixed 1000 µs loop window as proof of final duty without adding measured evidence; allowing Static to suppress semantic feedback, fences, input, or complete frames.

### `firmware/src/ui/render_state.h` (normalized presentation model, fan-out)

**Analog:** current `RenderState`, `RenderState::Slot`, and `CodexRenderView` (lines 5–77).

**Ownership and seam:** `AgentProjection` materializes one committed normalized view; themes and LED grammars consume it. It is not a second snapshot cache and must not duplicate host authority. Presentation-only phase/event metadata belongs here only if shared by display and LEDs; theme-local primitive details remain in theme files.

**Current shape** (lines 5–8, 56–77):

```cpp
// Shared presentation state consumed by every ThemeRenderer and LED grammar.
// Built by AgentProjection from its committed generation — never a second
// snapshot cache ...
struct RenderState {
  struct Slot {
    bool occupied = false;
    const char* title = "";
    const char* discriminator = "";
    const char* since = "";
    const char* age = "";
    TileState state = TileState::Empty;
    TileFeedback feedback = TileFeedback::Disabled;
  };
  CodexRenderView codex;
  DiagnosticsRenderView diagnostics;
  Slot slots[kSlotCount];
  const char* source_status = "";
  bool syncing = false;
  bool blocked_pulse_high = true;
};
```

**Extension rule:** Add bounded transition/event fields adjacent to `blocked_pulse_high` only when both themes and grammars need the value. Keep source status, `syncing`, tile identity, state words, Codex values, ages, and feedback authoritative and stable. A newer generation or stale/offline/SYNC fence must replace or invalidate ordinary presentation metadata immediately.

**Tests to copy:** `test_committed_render_state_exposes_one_codex_and_diagnostics_view` (`test_main.cpp:230-245`) proves this is a single view; `assertThemeVocabulary` (`test_main.cpp:664-703`) proves every renderer sees the same semantic vocabulary.

**Avoid:** adding a second host snapshot, mutable theme-specific copy of identity, numeric ticker values, or a phase field that can make LEDs and display disagree at a semantic moment.

### `firmware/src/ui/theme.h` and `firmware/src/ui/theme_common.h` (renderer contract and shared primitives)

**Analogs:** `ThemeRenderer` interface (`theme.h:35-57`) and `theme_common` state/menu helpers (`theme_common.h:32-80`, `272-460`).

**Renderer boundary:** Themes compose complete frames into the caller-owned sprite. The projection owns panel selection and `pushSprite`; the renderer never flushes.

```cpp
virtual void composeTile(LGFX_Sprite& sprite, uint8_t slot,
                         const RenderState& state) = 0;
virtual void composePanel4(LGFX_Sprite& sprite, const RenderState& state) = 0;
virtual void composeMenu(LGFX_Sprite& sprite, const MenuState& menu) = 0;
virtual void composeSync(LGFX_Sprite& sprite) = 0;
virtual uint8_t ambientTick(uint32_t now_us) { (void)now_us; return 0; }
virtual uint32_t ambientPeriodUs() const { return 0; }
```

Extend `ambientTick`/`ambientPeriodUs` and, if necessary, add a shared bounded transition input. Do not add a second per-theme scheduler. The existing default zero cadence is an intentional safe baseline.

**Shared semantic vocabulary:** `styleFor` maps state → literal word/color; `feedbackStyle` maps feedback → literal word/vehicle; `fenceWord` maps source status to `STALE`, `OFFLINE`, or `UNAVAILABLE` (`theme_common.h:37-80`). All new motion must sit behind these stable words and geometric cues. Do not let motion or hue become the only distinction.

**Menu analog:** `drawMenuRoot` uses a clamped three-row viewport, one selected row, fixed row coordinates, and per-theme presentation (Signal Edge selection band, Ledger dividers, Beacon centered copy, Instrument geometry) (`theme_common.h:332-385`). `drawMenuValuePreview` and `drawBrightnessTrack` (`405-460`) are the safe extension seams for transition visuals; candidate values already render immediately from `MenuState`.

**Avoid:** moving title/state/value baselines, making input wait for `ambientTick`, placing menu persistence in a theme, or adding a widget/UI framework.

### `firmware/src/app/agent_projection.{h,cpp}` (projection, safety fence, animation arbitration, capture)

**Analog:** current `AgentProjection` public seam (`agent_projection.h:54-109`) and its stage/commit/tick/capture implementation.

**Authority boundary:** The projection owns staged and committed generations, bindings, feedback lifecycle, complete-frame composition, sequential flush, and deterministic capture. `ThemeRenderer` owns geometry only. `MenuController` owns input state. `LedEngine` owns LED policy/application. Keep these boundaries intact.

**Staging and validation:** `stageSnapshot` constructs a local `Generation candidate`, validates epoch/status/revision, Codex and diagnostics nullability, bounded strings, and all three slots before setting `staged_` and `staged_valid_` (`agent_projection.cpp:306-457`). This is the pattern for adding bounded transition inputs: derive them from the committed generation and reject malformed data rather than invent defaults.

**Safe commit/reveal:**

```cpp
// agent_projection.cpp:520-541
// Bindings deactivate ... and activate only after the third flush.
disableActive(nullptr);
for (uint8_t slot = 0; slot < kSlotCount; ++slot) {
  if (!renderTile(board, theme(), staged_, slot, staged_.tiles[slot],
                  Feedback::Disabled)) {
    staged_valid_ = false;
    syncing_ = true;
    renderSync(board);
    return false;
  }
#ifdef ARDUINO
  board.update();
#endif
}
return commitSnapshot();
```

`renderTile` builds a `RenderState`, calls `renderer.composeTile(g_composition, ...)`, then performs exactly one `pushSprite` (`agent_projection.cpp:565-608`). Recovery or ordinary transition work must preserve one reusable PSRAM 128×128 RGB565 sprite and never expose mixed-generation pixels.

**Tick arbitration:** `tick` handles pending deadline and feedback hold before motion (`agent_projection.cpp:611-627`), then applies semantic dominance: fenced source returns without motion; BLOCKED and ambient due bits are selected; feedback suppresses ambient work while pending retains its bounded cadence (`629-648`). Extend this arbitration for ordinary transitions/recovery, but keep the order: urgent fence/SYNC → immediate feedback/menu response → current-generation semantic transition → ambient accent.

**Capture seam:** `capturePanel` selects the renderer, rejects menu scenes on agent panels, uses `captureFixture`/`codexCaptureFixture`/`menuCaptureFixture`, composes without flushing, and exposes `capturePixels()` (`agent_projection.cpp:679-701`). Add deterministic phase fixtures here only; do not mutate NVS, active bindings, or host state.

**Focus fencing:** `captureFocusIntent` binds action to opaque IDs, host epoch, snapshot revision, source revision, and slot (`agent_projection.cpp:764-784`). `applyFocusResult` requires all correlations and maps outcomes to exact feedback holds (`agent_projection.cpp:787-818`). Press impulse metadata must remain presentation-only and cannot turn `PENDING` into `FOCUSED`.

**Tests to copy:**
- Sequential complete frame and injected renderer: `test_flush_ordering_one_push_per_panel_sequential`, `test_theme_dispatch_renders_through_injected_theme` (`test_main.cpp:265-303`).
- Reveal fence: `test_reveal_window_press_is_inert` and `test_mid_reveal_failure_falls_back_to_sync_on_all_panels` (`361-427`).
- Feedback timing/correlation: `test_success_hold_is_shorter_than_failure_hold`, `test_pending_press_is_superseded_by_new_press` (`429-518`).
- Deterministic panel-4 capture: `test_phase3_capture_scenes_use_production_panel4_renderers` (`1090-1136`).

**Avoid:** queuing old transition frames, activating bindings between panel pushes, drawing a partial panel, flushing from a theme, accepting a transport delivery as focus success, or allowing a later ambient frame to repaint an urgent fence.

### `firmware/src/app/menu_controller.{h,cpp}` (immediate encoder/menu authority)

**Analog:** `MenuController::click`, `rotate`, `cancel`, `expire`, `takeBrightnessIntent` (`menu_controller.cpp:40-187`; declarations and bounds in `menu_controller.h:8-62`).

**Authority and bounds:** The controller owns the six-row root, three-row viewport, candidate/stored values, 30-second inactivity, persistence confirmation, and brightness intent. Presentation progress must be an additional timestamp/record, not a state transition that gates these methods.

**Immediate mutation pattern:**

```cpp
// menu_controller.cpp:123-157
if (mode_ == Mode::Root) {
  const uint8_t next = clampValue(static_cast<long>(state_.cursor) + delta,
                                  0, kRootRowCount - 1);
  if (next == state_.cursor) return false;
  state_.cursor = next;
  updateViewport();
  markDirty();
  return true;
}
...
state_.brightness_candidate = next;
emitBrightness(next);
markDirty();
return true;
```

`close()` immediately emits restoration when a brightness candidate differs, resets candidates to stored values, closes mode, and marks the view dirty (`40-52`). `confirmValue()` persists only on click (`61-73`). `expire()` calls the same close/revert path (`166-173`).

**Safe extension:** Record direction and presentation start/end at the projection/menu boundary after `rotate` or `click`; render the first new cursor/value in the same turn, then settle over ≤200 ms. A reversed detent should replace/reverse the presentation record, never add inertial momentum. Timeout/cancel must call existing `close()` immediately.

**Tests to copy:** `test_product_router_keeps_direct_keys_live_in_every_menu_mode`, `test_simultaneous_direct_keys_precede_click_and_rotation_dispatch`, `test_menu_controller_walks_six_clamped_rows_and_all_pages`, and `test_menu_brightness_previews_confirms_and_reverts_locally` (`test_main.cpp:1742-1916`).

**Avoid:** mutating settings during preview, delaying `board.setBrightness`, coalescing detents, wrapping rows, letting menu intercept keys 1–3, or making a renderer own candidate values.

## Shared Patterns

### Complete-frame composition
**Sources:** `agent_projection.cpp:49-59,565-608`; `theme.h:35-45`; `test_main.cpp:265-284`.

One PSRAM-backed 128×128 RGB565 sprite is reused. Themes compose into it; projection pushes one complete frame per panel. No partial drawing, second display abstraction, or per-frame allocation.

### Semantic preemption and generation fencing
**Sources:** `agent_projection.cpp:306-457,460-542,611-648`; `test_main.cpp:361-427`.

Stage/validate a complete generation, disable bindings, flush safe complete panels sequentially, and activate only after final commit. Urgent source/focus truth wins over ordinary transition and ambient work. Old transition frames are discarded when a newer authoritative generation arrives.

### Stable semantics under motion
**Sources:** `theme_common.h:32-80`; each theme `composeTile`; UI-SPEC §Shared Motion and Transition Contract.

Literal words, identity, ages, values, and primary geometry are stable. Motion changes only bounded accent primitives appropriate to the theme. Full/Half/Static all retain semantic completeness.

### Direct physical input causality
**Sources:** `product_input_router.cpp:11-26`; `main.cpp:574-608,634-660`; `menu_controller.cpp:123-187`; `test_main.cpp:1666-1829`.

`board.update()` and input capture happen before USB, animation, menu rendering, and LEDs. Agent slots are emitted before encoder actions; brightness is applied in the same turn. Animation is presentation-only and cannot gate keys or menu authority.

### Shared semantic event, grammar-owned LED choreography
**Sources:** `led_grammar.h:18-22,57-64`; `led_engine.cpp:29-67,69-107`; four grammar files.

Display and LEDs may share an event epoch/semantic phase, but each grammar owns its masks, resting restraint, and choreography. `LedEngine` remains the final cap/dominance/deduplication boundary.

### Paired logical + physical evidence
**Sources:** `capture_panel.py:90-134`; `phase3_smoke.py:295-479`; `.agents/skills/screen-capture-flow/SKILL.md:13-20`.

Logical RGB565 artifacts prove pixels; exact-device observations prove brightness, optics, LED mapping, interaction feel, latency, and smoothness. Both must be deployment-linked and preserve failed/degraded evidence.
