Purpose: Replace Linux shell/PID assumptions without inventing supervision, live settings, logging, or status APIs Herdr does not provide.
Output: Config, lifecycle, control, status, logging ports and focused lifecycle/resource tests.
</objective>

<threat_model>
## Trust boundaries

| Boundary | Description |
|---|---|
| Local user process to control IPC | Lifecycle mutations and status requests cross process authority. |
| Config files to running process | User-controlled values influence child paths, timing, and diagnostics. |
| Runtime failures to status/log output | Sensitive upstream material can escape through diagnostics. |

## STRIDE threat register

| Threat ID | Category | Component | Severity | Disposition | Mitigation plan |
|---|---|---|---|---|---|
| T-04-19 | Spoofing | Control IPC | high | mitigate | Exclusive lock authority, 0700 state directory, same-user peer check, version/config identity. |
| T-04-20 | Tampering | Startup config | high | mitigate | One closed file under Herdr config dir, strict validation, canonical digest, restart-only application. |
| T-04-21 | Information disclosure | Status/tracing | high | mitigate | Allowlisted codes/fields, field and payload caps, recursive privacy tests, default-off stderr sink. |
| T-04-22 | Denial of service | Control/history/events | medium | mitigate | 16 KiB payload caps, bounded channels, 32-record ring, deterministic capped backoff. |
| T-04-23 | Elevation | Lifecycle actions | high | mitigate | Separate read-only status from explicit mutating commands and reject cross-user peers. |
</threat_model>
