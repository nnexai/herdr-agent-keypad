### Warnings

#### WR-06: Evidence/checksum pair remains inconsistent across a power-loss window

**Severity:** WARNING  
**File:** `tools/phase1_bringup/src/phase1_bringup/evidence.py:542-547`  
**Issue:** `atomic_write_pair()` makes each pathname durable separately. If the process is terminated or the system loses power after `os.replace(content_temp, path)` and its directory fsync at lines 542-544, but before the checksum sidecar replacement at lines 545-547, recovery leaves the new JSON with the old sidecar digest. The in-process `except` rollback cannot execute after such interruption. Therefore Phase 02.2 evidence is still not self-consistent or reliably hash-addressable after the interruption class named by the original finding.

**Fix:** Commit one atomic evidence envelope that contains both the JSON payload and its digest, then derive or verify any human-readable sidecar after loading the committed envelope. Alternatively, add a durable generation/commit marker that names both immutable generation files; readers must reject a generation unless the marker and both hashes agree. Add a failure-injection recovery test that simulates interruption after the content replacement and verifies readers reject the incomplete generation rather than accepting it as evidence.
