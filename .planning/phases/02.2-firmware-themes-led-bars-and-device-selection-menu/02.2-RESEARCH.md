# Phase 02.2: Firmware Themes, LED Bars, and Device Selection Menu — Research

**Researched:** 2026-08-18
**Method:** Inline inventory of the existing firmware seams, the design-proposal behavioral source, the pinned toolchain, and the locked contracts that Phase 02.2 must amend or preserve.

## Existing Firmware Inventory (verified by source read)

### Renderer and projection seam

- `AgentProjection` (firmware/src/app/agent_projection.h/.cpp) owns three staged/committed slots, `TileState` (17 values covering empty/blocked/unseen/working/idle/settled/unknown/stale/offline/unavailable/sync/pending/focused/rejected/vanished/uncertain/failed), `Feedback` (10 values), generation staging, identity-bound focus bindings, `captureFocusIntent`, and `applyFocusResult`.
- Rendering today is a single hardcoded language inside `AgentProjection::renderTile`/`renderSync`: one translation-unit `LGFX_Sprite g_composition` (128×128 RGB565, PSRAM-preferred, created once via `ensureComposition()`), fully composed then flushed once per panel with `pushSprite(display, 0, 0)`. This is the Phase 02.1 accepted compose-then-flush model. **Theme work must extract the presentation (renderTile/renderSync bodies) behind a theme seam while leaving staging/commit/binding/feedback logic untouched.**
- `commitSnapshot(BoardAdapter&)` disables all bindings, composes+flushes slots 0..2 sequentially, and activates bindings only after all three flushes succeed. Failure keeps SYNC/disabled and rejects the ACK.
- Feedback timing constants: `kPendingDeadlineUs = 3 s`, `kFeedbackHoldUs = 2 s`. D-15 requests ~800 ms success hold; failure-family remains until newer generation or bounded timeout. The 800 ms hold is a presentation-layer duration; the 2 s value is currently shared by all feedback outcomes and must be split (success ≈ 800 ms, failure family retains the longer bound).

### Hardware boundary

- `BoardAdapter` is the only hardware path: `displayAt(0..3)`, `wasPressed(0..4)`, `encoderDelta()`, `encoderPosition()`, `mapEncoderClick()`, `setBrightness()`, `setLeds(hue, sat, brightness, logicalMask)`, `clearDisplays()`. LED output resolves through `PhysicalMap::ledMask()`; no raw index path exists.
- `PhysicalMap::loadVerified()` — delivered-unit identity mapping: displays 0..3 ↔ library 0..3, keys 0..4 ↔ library 0..4, encoder click = key 4, cw sign +1, 14 LEDs logical=library. Verified and human-confirmed in Phase 1.
- `BoardAdapter::setLeds` applies **one HSV triple to a mask** per call. Grammars needing different hues on different LEDs simultaneously must issue multiple sequential `setLeds` calls (one per hue group). The official library layers these calls; the last write per index wins. LED grammar engine must therefore emit a bounded ordered list of (mask, hue, sat, brightness) segments per LED frame.
- Physical LED zones (from DESIGNER-ONBOARDING/DESIGN-PROPOSALS, authoritative 14-index map):
  - Backlights: L1 (K1), L4 (K2), L7 (K3), L10 (K4/usage), L13 (encoder).
  - Above-key accents: L0, L3, L6, L9. Inter-key accents: L2, L5, L8, L11, L12.

### Input and runtime loop

- `main.cpp` `loop()`: `board.update()` → `readFrames()` → `agentProjection.tick(board, now)` → `reportAgentKey()` → `delay(1)`. Encoder is currently consumed only by the Phase 1 bring-up probe path (`reportInput()`, armed via `probe` frames); **normal runtime never reads `encoderDelta()` or encoder click — the menu integration point is a new poll in `loop()` that never gates `reportAgentKey()`**.
- `reportAgentKey()` handles keys 0..2 only; key 3 (K4) and key 4 (encoder click) are unbound in normal runtime. Menu may consume encoder click (logical key 4 via `mapEncoderClick`) without touching the focus path.
- Bring-up renderer (`ui/bringup_renderer.h`) is a separate temporary surface still used by `render()`/probe flow; theme runtime must not route through it.

### Persistence boundary

- No device persistence exists today except LittleFS being configured in `platformio.ini` (`board_build.filesystem = littlefs`) and never mounted in source. ESP32 Arduino `Preferences` (NVS) is available in the pinned Arduino-ESP32 3.3.11 core with no new dependency.
- **Decision: use `Preferences` (NVS namespace `keypad`, keys `theme`, `ledgram`, plus a settings schema version).** Rationale: two small enums, atomic key writes, no filesystem mount/format lifecycle, survives reflash of app partition. Values are validated on read; out-of-range/missing → Signal Edge + safe LED default without writing back (a fallback is not a user confirmation, per D-12).
- Persisted content is strictly device-owned presentation settings. No host data, identities, epochs, or bindings are ever persisted (D-11).

### Native test seam

- `test/agent_projection/` compiles production `agent_projection.cpp` against stub `TKeyboardS3Pro.h` (fake `Display`, `LGFX_Sprite` call log, ButtonSense, controllable time) under `env:native-agent-projection`. Theme/LED/menu logic should be structured so the same harness (or sibling environments) covers it: pure state machines + call-log render assertions.
- Selected build: `pio run -e selected-usb`; native: `pio test -e native-agent-projection` via `tools/phase1_bringup/.venv/bin/pio`.

## Design Source Extraction (DESIGN-PROPOSALS.html)

### Shared semantic contract (all themes)

- State vocabulary, color anchors, glyphs, and mandatory colorblind-safe second channel per state (rail pattern / typography / glyph geometry / ring stroke). Colors match the already-implemented palette in `agent_projection.cpp` (`#F7768E`, `#7DCFFF`, `#E0AF68`, `#9ECE6A`, `#565F89`, `#22D3EE`, `#EF4444`, bg `#0B0F14`).
- Text tiers: T1 title/state 10–12 px cell (8 px cap), T2 meta 8 px cell (5×7 glyph) hard floor; glyphs are drawn primitives 24–44 px, never font glyphs. Truncation is budgeted per field with ellipsis; text never shrinks below floor (D-02).
- Truth rules: null ≠ 0, stale visibly fenced, failure never shows success, empty never focusable, UNKNOWN vs SETTLED share hue but never glyph/edge.

### Four display languages

| Theme | Defining geometry | State channel | Render cost |
|---|---|---|---|
| A Signal Edge (default, D-03) | 16 px left rail; quiet type; bottom feedback band y:108..128 | rail width+pattern (16 solid / 8 thin / animated dashes / 3-1-3 stripes / hollow / dotted / none) | lowest |
| B Ledger | typographic row: header disc·age, hairline, 2-row title, state row w/ 5 px underline, footer slot dots | type weight + underline style + BLOCKED full-band inversion; feedback = opaque header band takeover | low |
| C Beacon | 44 px center glyph on radial tinted field; title strip last | glyph geometry + field presence; feedback = center takeover overlay | highest (full-field redraw; RGB565 banding risk) |
| D Instrument | ⌀64 ring dial in corner-ticked bezel; state ring stroke style | ring stroke (solid/thin/dashed/double/dotted/hairline); health = red bezel ticks; feedback = ring recolor | medium (arc primitives need bring-up validation) |

Panel-4 compositions per theme exist in the proposal (stacked gauges / ledger numbers page / conic dial / twin gauges) with truthful unavailable/stale/auth-failed/offline/limit-reached states. **Phase 02.2 has no Codex collector: panel 4 at rest renders each theme's honest UNAVAILABLE composition (no fabricated values); full truthful data wiring is Phase 3.**

### Four LED grammars (real 14-pixel strip)

| Grammar | Resting policy | Health | Focus feedback |
|---|---|---|---|
| A Rail Echo | only 5 backlights mirror tile state (BLOCKED 40 pulse / UNSEEN 30 / WORKING 18 / IDLE 8 / others off) | all backlights breathe dim red in unison | pressed backlight cyan → lime×2 / red×2 |
| B Exception Channel | dark unless action required (BLOCKED rose 30 breathe, UNSEEN blue 20; nothing else) | above-key accents 0/3/6/9 dim red 10 | display-only (grammar-specific cue = deliberate darkness; still bounded per D-08 — implement as a single brief backlight blink, the grammar's minimal bounded cue) |
| C Field Extension | 3-LED halo per key (K1:0-1-2, K2:3-4-5, K3:6-7-8, usage:9-10-11) in state hue, backlight brightest | halos off; encoder pair 12-13 breathes red 10 | halo sweep during PENDING, lime/red blink ×2 |
| D Meter + Lamps | backlights as grammar A; accents L0-L2-L3-L6 = 4-step usage meter (off in 02.2 = honest no-usage-data) | lamps unison dim red; meter dark | lamp blink, meter untouched |

Note on D-08 vs grammar B: the proposal specifies B's press feedback as display-only. D-08 requires every grammar to provide a bounded LED cue. Resolution recorded for the planner: grammar B gets a minimal bounded cue (single short pressed-backlight blink for pending/success/failure with distinct hue), preserving its darkness philosophy while satisfying D-08. This is a bounded extension, not a contradiction.

- Power defaults (as defaults per D-07, not hard caps): global brightness 45, resting ≤ 25, ≤ 6 LEDs above 25, no persistent white, unison-red health ≤ 10, dim mode ≤ 8, all-off single mask write. Safe values must still be sighted on the real unit during the device smoke.

### Motion charter and its amendment

The proposal charter is discrete keyframes with BLOCKED-only persistent motion (2 alternating frames at 1.2 s). The user overrode this in discussion (D-13/D-14): theme-specific ambient motion, continuous frame animation, per-panel atomic reveal (D-16). Reconciliation is decided below.

## Contract Reconciliation (decided; record in REQUIREMENTS/ROADMAP during Wave 1)

### R-1: Decorative/ambient animation (amends REQUIREMENTS.md out-of-scope row; supersedes proposal BLOCKED-only charter)

Permitted, under a **measured animation budget**:

1. Every animation frame is a complete composition flushed once (compose-then-flush is inviolable; no partial redraw, no per-pixel flush-time alpha).
2. Animation is a bounded frame scheduler in `tick()`: per-theme ambient cadence with a global ceiling derived from the **measured** per-panel compose+flush cost (`ProofMetrics::max_display_flush_us` from the selected build; Phase 02.1 already measures it). Rule: total animation flush time ≤ 30 % of loop wall time; scheduler degrades (halves cadence, then freezes to a static frame) if the measured budget is exceeded. Frame-rate cap decided at implementation from real measurements, not assumed.
3. Semantic dominance: stale/offline fencing, feedback bands, SYNC, and state changes always preempt and are never obscured or delayed by ambient motion. BLOCKED motion keeps its 1.2 s period and stays synchronized with LED pulses.
4. Ambient motion is theme-specific and must not carry meaning absent from static channels (it may not become a fourth state channel).
5. Heap invariant: no per-frame allocation; the single reused sprite (plus at most one additional bounded PSRAM sprite if a theme needs a cached background) serves all animation.

### R-2: Per-panel progressive reveal (amends SYNC-02 phrasing; preserves its safety intent)

- **Bindings remain all-panel atomic.** All three bindings deactivate at stage time and activate only after all three panels flushed successfully — unchanged from Phase 02.1. A press during the reveal window is impossible to bind to mixed pixels because no binding is active.
- **Pixels may reveal per-panel**: each panel flips directly from its old complete frame to its new complete frame (no SYNC veil between generations for ordinary refreshes), sequentially, target ≤ 250 ms total for three panels. The SYNC presentation remains for boot, session reset, and failure paths.
- SYNC-02's protected property is restated as: "rendered pixels of any *actionable* binding always represent exactly one logical host epoch and revision." The transient non-actionable mixed-pixel window (sub-250 ms, keys fenced) is explicitly accepted. FOCS-01..04 are unaffected.
- Failure mid-reveal (flush error) falls back to SYNC/disabled on all panels and a rejected ACK, exactly like today.

### R-3: Feedback timing (D-15)

Success hold ≈ 800 ms then return to resting state; pending appears immediately; failure family holds until newer generation or the existing bounded timeout (keep 2 s hold constant for failure/uncertain, replace the success path's use of `kFeedbackHoldUs` with an 800 ms constant).

## Architecture Decision: theme/LED seams

- **`RenderState`** (new, plain struct): per-slot {occupied, title, discriminator, TileState, Feedback, source_status}, plus global {syncing, menu state, settings}. Built by `AgentProjection`/menu, consumed by themes and LED grammars. Single source; no second snapshot cache.
- **`ThemeRenderer`** (interface, 4 implementations): `composeTile(sprite, slot, RenderState)`, `composePanel4(sprite, RenderState)`, `composeMenu(sprite, MenuState)`, `ambientTick(...)` returning whether a recomposition is needed. All draw into the existing shared sprite; flushing stays owned by the projection/commit path.
- **`LedGrammar`** (interface, 4 implementations): consumes the same `RenderState` + focus feedback events, emits ≤ N bounded (logical mask, hue, sat, brightness) segments per LED frame; a single engine applies segments through `BoardAdapter::setLeds` and enforces the global brightness/dim/all-off policy.
- **`SettingsStore`**: NVS-backed theme + LED grammar enums with schema version and safe fallback.
- **`MenuController`**: panel-4 overlay state machine (closed → rows → preview → confirm), encoder click/delta driven, clamped rows (D-12), preview volatile (D-04/D-11). Keys 0..2 remain live throughout (D-10).

## Open Hardware Questions (validated during the device smoke, not blockers)

1. 8 px-cell (5×7) legibility on the physical GC9107 panels — if it fails, meta lines drop, never shrink.
2. LovyanGFX arc/ring stroke quality at ⌀64 for Instrument (dashed/double/dotted rings) — fallback is polygonal ring segments.
3. Perceived LED brightness ladder 8/18/30/40/45 on the real strip under USB power (D-07 measurement).
4. Radial field banding in RGB565 for Beacon — may need ordered dither or stepped bands.
5. Whether inter-key accents read as belonging to left or right key — finalizes Field Extension halo sets; current proposal sets are the default.
6. Measured animation budget numbers (compose+flush per panel) to fix ambient cadence.
