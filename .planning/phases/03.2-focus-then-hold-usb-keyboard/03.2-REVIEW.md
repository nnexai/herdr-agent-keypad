## Summary

I traced the Plan 09 qualification path from `run_phase32_qualification()` through the controlled CDC fixture, evdev observer, final-qualification builder, artifact writer, and hash-only Phase 4 gate. I also reviewed the final-validator and runner tests.

The published artifacts are current and hash-linked to deployment `9a04faad5282b266bef6a75118d1e414b7a73c7f51485c74332da60d217321cd`; the exact-device run also recorded an external evdev trace ending in `UP`. That is useful evidence for deployment identity and the terminal observed input state. It does **not**, however, prove the Plan 09 machine rows, CDC load, latency, lifecycle, exact focus/session correlation, or 300-case stress: the reviewed runner constructs those values independently of device observations. Therefore the current `pass` gate must not be used as the Phase 4 release prerequisite.

## Critical Issues

### CR-01: Qualification fabricates the production matrix instead of reconciling device observations

**File:** `tools/phase1_bringup/src/phase1_bringup/composite_qualification.py:459-606`, called by `tools/phase1_bringup/src/phase1_bringup/phase3_smoke.py:2382-2389`

**Issue:** `build_final_qualification()` generates every stress record, focus result, HID sequence, firmware counter, row status, and (when callers do not override them) all CDC and latency measurements. In particular, lines 490-520 synthesize 300 records and `[1, 2, 0]` HID sequences; lines 521-531 default latency to 100 × 1 ms and CDC counters to 2,000 in both directions; and lines 532-540 mark every required row observed and passing. The runner passes only deployment lineage, the terminal input-oracle summary, and command-result metadata (lines 2382-2389). It never supplies measured stress records, HID transitions, per-row results, CDC counts, latency samples, or final firmware counters.

This defeats HOLD-01 through HOLD-05 and SAFE-02 rather than qualifying them. A device that produces unauthorized HID, misses release-all, fails lifecycle recovery, cannot carry the 4,096-byte CDC envelope, or exceeds the latency bound can still publish a hash-valid Phase 4 `pass`. The regression fixtures reinforce this behavior by constructing the same synthetic evidence rather than proving a measured-data contract (`test_composite_qualification.py:697-817` and `test_phase3_smoke.py:1456-1479`).

**Fix:** Make the qualification builder a strict validator/serializer of immutable measured records. Collect each row's scheduled input, observed exact focus/session frame, raw HID events, firmware metrics, CDC transactions, and timestamped latency samples in the runner; require one-to-one reconciliation before assigning a row `pass`. Remove all default measurements and all generated pass records. Tests must demonstrate rejection when a required measured input is absent or cannot be linked to its row.

### CR-02: The gate accepts a preflight session that is different from the deployment session

**File:** `tools/phase1_bringup/src/phase1_bringup/phase3_smoke.py:2383-2397`; `tools/phase1_bringup/src/phase1_bringup/composite_qualification.py:597-603, 653-666`

**Issue:** The runner stores the actual fixture hello, including boot/session data, only in unchecked `device_preflight` after `build_final_qualification()` has copied the expected deployment tuple into `qualification["deployment"]`. `validate_final_qualification()` then compares that copied tuple to the deployment file, not the observed hello/session. It never validates `device_preflight` at all. The current artifact demonstrates the gap: its checked deployment tuple lists boot `0000fccb0deabf8c-04ccea8c` and session `session-0f609383aa8f890c`, while `device_preflight.hello` records boot `0000fccb0deabf8c-321bd141` and session `session-b39b92099d479ff8`.

This is a fail-open identity/session boundary. A qualification run against a rebooted, stale, or otherwise different session can be accepted as the locked deployment, violating HOLD-05 and the replay/spoofing mitigations for T-03.2-09-03 and T-03.2-09-04.

**Fix:** Have the runner derive the checked deployment boot ID and session ID from the live paired hello used for qualification, and reject if either differs from the deployment lock before any row can pass. Put the observed tuple in a closed, validated field (or eliminate the duplicate field), and test a mismatched preflight hello/session through `validate_phase32_gate_file()`.

### CR-03: Physical rows are declared passing without a row-specific machine invariant

**File:** `tools/phase1_bringup/src/phase1_bringup/phase3_smoke.py:1746-1778, 1829-1841`

**Issue:** `_phase32_physical_rows()` assigns every D-01–D-18 row `machine_invariant: "pass"` and `result: "pass"` unconditionally once the operator answered `Y` to one of three broad prompts. It does not consume qualification rows, raw evdev events, controller evidence, lifecycle observations, or a row-specific invariant. `write_phase32_final_artifacts()` invokes it directly. The later validator checks only these asserted strings (`validate_phase32_device_evidence()`, lines 1481-1497), so a physical observation cannot be rejected when its paired machine condition failed or was never measured.

This violates Plan 09's explicit rule that physical acceptance must not overrule a failed ordering, session, lifecycle, CDC, latency, or stuck-key invariant. It also allows a single prompt response to certify individual D-01–D-18 claims that were not separately observed.

**Fix:** Define the concrete machine evidence required by each D row and store a hash/reference to it in that row. Generate `machine_invariant` from the already-validated corresponding machine record, never from a literal. Keep physical observations as typed supplemental evidence, but require both the row-specific machine proof and the relevant operator observation before emitting `pass`.

### CR-04: Evdev observer failures are lost in a daemon thread, allowing a partial trace to pass

**File:** `tools/phase1_bringup/src/phase1_bringup/phase3_smoke.py:2015-2038, 2288-2323`

**Issue:** `_phase32_start_observer()` runs `_phase32_capture_input_until()` in a daemon thread. Any `os.open`, `os.read`, selector, or partial-`input_event` failure terminates that thread, but the exception is neither recorded nor re-raised. `_phase32_stop_observer()` merely joins for five seconds and returns whatever events were captured. Since input events from earlier prompts are aggregated, a later observer failure can leave an older well-formed UP trace that satisfies `validate_input_trace()` and allows the final artifact to pass.

The external UP/DOWN oracle is the primary stuck-key/lifecycle control (HOLD-04/HOLD-05, T-03.2-09-02). Silently losing the observer during unplug, suspend, reset, or release removes that control rather than failing closed.

**Fix:** Give the observer a result object/queue containing either complete events or an exception; after joining, require that the thread terminated successfully and completed its capture before proceeding. Associate each capture interval with its row and reject the run on any observer error, timeout, unexpected thread liveness, or missing required transition.

## Warnings

### WR-01: Partial final-artifact writes permanently prevent recovery after an interrupted publish

**File:** `tools/phase1_bringup/src/phase1_bringup/phase3_smoke.py:1804-1882`

**Issue:** The function writes qualification, evidence, ledger, and gate sequentially. If a later write or final reopen validation fails, earlier files and their sidecars remain. A later invocation refuses to replace any existing final artifact (lines 1824-1826), so the normal runner cannot recover or record a corrected final set in the same output root. This is particularly likely at the final hash-validation boundary and leaves incomplete release evidence that requires manual filesystem intervention.

**Fix:** Write the complete artifact set into a unique staging directory, validate all paths and sidecars there, then atomically publish the directory (or an immutable manifest pointer). On failure, preserve the failed staging attempt separately and leave the final output location without a partial set.
