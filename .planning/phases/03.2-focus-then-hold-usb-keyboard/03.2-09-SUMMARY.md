## What changed

The lifecycle observer now treats required unplug, reset, and remount behavior as expected only during the lifecycle interval. It closes the old evdev node, finds the same `303a:1001` device with serial `8C:BF:EA:0D:CB:FC`, admits its fresh boot/session over CDC, grabs the replacement input node, and requires Space to end UP. Device removal remains fatal during threshold and presentation checks.

The final identity validator now uses the measured lifecycle recovery session. The pre-lifecycle deployment session is intentionally stale after reset and cannot be the final session identity.

Plan 09 also gained a real production measurement provider. A native probe executed `HoldController`, `ProofMetrics`, and `FixedSpaceHid` for 1,365 observations. This includes the frozen 300-case stress schedule and 100 latency cases. The exact device then processed 2,000 CDC request/ack round trips in each direction. An overlong 4,097-byte frame was rejected, the next valid frame passed, and all strict counters remained zero.

## Exact-device result

The preserved physical run completed threshold, presentation, and lifecycle checks. Lifecycle evidence contains two exact same-serial remounts:

- boot `0000fccb0deabf8c-86c0e2f8`, session `session-5e85c0bf3e8c2825`
- boot `0000fccb0deabf8c-5ed5eb59`, session `session-beac0966a5ff40a3`

The final input oracle is `UP`. The defect ledger has no entries. No physical batch was repeated.

The earlier unattended same-boot USB failure remains below the evidence boundary. The host logged `device descriptor read/64, error -71` while the MCU retained the same boot and reset state. A later 300-second run on unchanged hardware did not reproduce it. This work does not claim a cable, connector, port, controller, PHY, power, or USB-stack root cause.
