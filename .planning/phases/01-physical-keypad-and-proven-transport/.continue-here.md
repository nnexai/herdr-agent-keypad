# BLOCKING CONSTRAINTS — Read Before Anything Else

- [ ] **Runtime HID is not the tracer serial link** — the board's `303a:1001` runtime endpoint is only a HID keyboard. Do not treat it as `/dev/ttyACM0`, a flash port, or proof that the tracer is running. Enter bootloader mode with KEY5/BOOT-0 and use the newly appearing USB JTAG serial node.
- [ ] **Physical evidence must be human-confirmed** — firmware acknowledgements and host receipt are not proof of a panel/key mapping. Do not record `Y PANEL-1` until the visible stimulus and physically pressed matching key are confirmed.
- [ ] **Build source root must remain explicit** — PlatformIO must use `src_dir=firmware/src`; without it the build links Arduino's `setup()`/`loop()` against no project entrypoint and fails with undefined references.
- [ ] **Python 3.14 is not exact Python 3.11 evidence** — the current venv passes the `>=3.11` floor and resolves pyserial 3.5, but the plan's exact Python 3.11 acceptance evidence is still missing. Do not claim it is satisfied.

## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|----------------------|
| HID/CDC conflation | The existing firmware enumerates as a keyboard HID device, which has no serial node and cannot run the tracer protocol. | blocking | Always verify the bootloader `/dev/serial/by-id` node before upload and the post-flash CDC node before running the tracer. |
| ACK-as-observation | A firmware probe acknowledgement can succeed even when the user pressed the wrong physical key. | blocking | Require explicit visible `Y/N/R` confirmation bound to `PANEL-1`; never infer physical PASS from frames. |
| Wrong PlatformIO source root | Default PlatformIO source discovery omitted `firmware/src`, producing a linker failure for `setup()` and `loop()`. | blocking | Keep `src_dir=firmware/src` in `platformio.ini` and rerun the project-venv build after any source-layout change. |
