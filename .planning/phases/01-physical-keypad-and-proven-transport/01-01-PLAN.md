<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Linux operator → guided utility | Human confirmation changes durable tracer evidence. |
| Host byte stream → firmware parser | Host-controlled or corrupt bytes cross into constrained firmware memory and dispatch. |
| Firmware reports → EvidenceWriter | Machine facts must remain distinct from physical observation. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-01-01 | Tampering | Firmware frame parser | high | mitigate | Count bytes before parsing, enforce closed v1 types and correlation, and reject unknown or oversized frames before dispatch. |
| T-01-02 | Spoofing | Guided physical confirmation | high | mitigate | Bind Y/N/R to visible step/run identity and never infer physical PASS from firmware acknowledgement. |
| T-01-03 | Repudiation | EvidenceWriter | high | mitigate | Atomically preserve manifest/result, finalize hashes, and reopen/schema/hash-verify the real tracer evidence. |
| T-01-SC | Tampering | Python/PlatformIO dependency resolution | high | mitigate | Pin immutable firmware sources and pyserial 3.5, use the plan-owned Python 3.11 environment, and stop on resolution mismatch. |
| T-01-04 | Information Disclosure | Host/device UI | low | accept | Only bounded revision/run suffix/physical facts display; no credentials, prompts, transcripts, or host paths are retained. |
</threat_model>
