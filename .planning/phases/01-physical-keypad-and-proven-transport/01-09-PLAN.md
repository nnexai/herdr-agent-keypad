## Phase Goal

**As a** user of the delivered T-Keyboard S3 Pro, **I want to** operate it through a verified physical map and a host link selected from real measurements, **so that** later keypad behavior rests on the exact unit and a proven transport.

<objective>
Close the production-runtime disconnect identified by CR-01, CR-18, and WR-01/WR-02/WR-06/WR-07/WR-08 while preserving all already verified renderer, UI, pairing, and USB-only composition behavior.

Purpose: Make the tested frozen protocol/session the only path that can reach flashed hardware side effects.
Output: One integrated production admission/dispatch path, real queue lifecycle metrics, bounded serial writes, persistent board readiness, and a live physical mapping source.
</objective>

## Trust Boundaries

| Boundary | Description |
|---|---|
| Selected USB bytes → production codec | Corrupt or replayed bytes enter constrained firmware memory. |
| ProtocolSession → hardware dispatch | Only current-session typed commands may cause physical side effects. |
| Board initialization/map → probe acknowledgement | Missing hardware readiness or mapping must fail closed. |
| Serial write/read → session accounting | Partial I/O must not become acknowledged or replayable work. |
