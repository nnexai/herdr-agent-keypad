## Summary

Phase 2 is physically accepted, but the current host is not a complete live projection loop. `PermanentBridge.bootstrap()` calls `events.subscribe`, yet `HerdrClient` performs one request per Unix-socket connection and returns only that response; `PermanentBridge.run_once()` polls USB focus frames and never consumes an asynchronous Herdr event stream or schedules refreshes [VERIFIED: `host/herdr_keypad/src/herdr_keypad/herdr.py:25-30,39-77`; `host/herdr_keypad/src/herdr_keypad/bridge.py:575-603,645-660`]. `InboxProjection` documents events as invalidation triggers, but no event-to-refresh implementation exists [VERIFIED: `projection.py:195-220`; `bridge.py:549-550`]. This is the highest-confidence synchronization gap.

Firmware stages exactly three records and commits bindings only after sequential draws; selected-device evidence records `WAIT/IDLE`, empty rejection, `PENDING`, exact focus, `FOCUSED`, and `BLOCKED` restoration [VERIFIED: `firmware/src/app/agent_projection.cpp:97-190,292-343`; `artifacts/phase2/automated-acceptance.json:3-31`; `02-04-SUMMARY.md:85-93`]. But `renderTile()` calls `fillScreen()` and many direct primitives/text writes, while replacement first draws a full-panel `SYNC` veil. The visible transition has no off-screen composition boundary and can expose sequential/partial panel updates [VERIFIED: `agent_projection.cpp:152-205,207-256`; `board_adapter.cpp:81-89`].

**Primary recommendation:** Add a host-owned, coalesced invalidation-to-complete-snapshot loop and explicit snapshot-ACK fencing, then make each three-slot tile compose completely before visible flush. Keep Phase 1 framing/session, Phase 2 ordering/identity/focus, fixed slots, and no-replay semantics.

## Architecture Patterns

```text
Herdr event/session -> host invalidation/coalescing -> complete snapshot/list/workspace
       -> InboxProjection (rank/seq, fixed 3) -> USB publish + snapshot_ack
       -> FrameCodec/Session -> stage -> compose complete tiles -> commit pixels/bindings
       -> key focus_intent -> host exact revalidation -> agent.focus -> focus_result
```

1. **Bootstrap + invalidation, never partial-event projection.** Prior research records `{event,data}` event envelopes and directs refresh of `agent.list` or full `session.snapshot` after event-stream reconnect [VERIFIED: `.planning/phases/02-authoritative-agent-projection-and-exact-focus/02-RESEARCH.md:276-290`; [CITED: https://herdr.dev/docs/socket-api/]]. Coalesce bursts into one in-flight refresh plus at most one follow-up. On failure, stale/offline disables bindings. Compare normalized payloads before publishing if that policy is locked.
2. **Generation-bound focus fencing.** Keep host epoch, snapshot revision, slot, entry ID, pane/terminal/session/source revision together [VERIFIED: `bridge.py:46-61,104-130`; `agent_projection.cpp:292-309`]. New generation clears pending actions and old bindings only after replacement rendering/ACK [VERIFIED: `agent_projection.cpp:152-190`]. Timeout/link interruption is uncertain/offline, never auto-retry [VERIFIED: `serial_link.py:94-136`].
3. **Compose then flush.** Preserve current geometry/copy/cues [VERIFIED: `agent_projection.cpp:207-256`; `02-UI-SPEC.md:53-73`]. Build a complete 128x128 tile in reused bounded storage (or equivalent), then flush through one `displayAt()` at a time. Keep `SYNC`/disabled until all three succeed; no animation [VERIFIED: `board_adapter.cpp:81-89`; `02-UI-SPEC.md:68-73,164-179`]. Buffer API/RAM/timing is an implementation checkpoint, not assumed.

- v2 types are exactly `agent_snapshot`, `snapshot_ack`, `focus_intent`, `focus_result` [VERIFIED: `protocol/schema/v2.json:8-24`; quote: `"enum": ["agent_snapshot", "snapshot_ack", "focus_intent", "focus_result"]`]. Do not invent event frames.
- Encoded line max is 4096 including LF, IDs max 64, digest FNV-1a-64 [VERIFIED: `protocol/schema/v2.json:5,26-31,99-101`; quote: `"x-max-encoded-line-bytes-including-lf": 4096`].
- Every snapshot has exactly three unique slots and explicit empties [VERIFIED: `bridge.py:209-233`; `agent_projection.cpp:101-147`].
- Order is rank ascending, then descending `state_change_seq` [VERIFIED: `projection.py:144-162,173-185`; quote: `normalized.sort(key=lambda entry: (entry.rank if entry.rank is not None else 99, -entry.state_change_seq))`].
- Same epoch requires increasing revision; changed epoch may lower revision [VERIFIED: `agent_projection.cpp:109-113`].
- Pixels and bindings commit only after all staged draws succeed [VERIFIED: `agent_projection.cpp:178-190`; `.planning/STATE.md:107-108`].
- Focus success requires exact pending action/generation/identity and `focused=true` [VERIFIED: `agent_projection.cpp:312-343`; `.planning/REQUIREMENTS.md:23-28`].
- Device action remains only `agent.focus`; triage/arbitrary calls excluded [VERIFIED: `bridge.py:497-507`; `02-VERIFICATION.md:58-63`].
- Disconnected/uncertain actions are never queued/replayed [VERIFIED: `.planning/REQUIREMENTS.md:39-44`; `serial_link.py:94-136`].

## Likely Implementation Slices

1. **Host live invalidation/refresh:** consume installed event stream or bounded complete-snapshot polling fallback; coalesce bursts; refresh through `InboxProjection`; re-establish after event reconnect; preserve rank/plugin authority.
2. **Publication/ACK fencing:** one in-flight snapshot and matching ACK; decide queue-versus-input-fence for interleaved focus during `request_v2`; test stale/mismatched ACK/session.
3. **Ready/freshness state:** ready only after complete current device ACK; source failure disables bindings. Keep full restart tour in Phase 4 unless ownership changes.
4. **Firmware composition:** fixed slots, labels, `SYNC`, stage/commit, focus correlation unchanged; add bounded compose-then-flush; measure heap/flush metrics.
5. **Feedback/refresh races:** late result cannot become success; new generation clears pending/deadline state. `commitSnapshot()` resets feedback but not visibly `feedback_until_`; verify/clear this generation-scoped timing state if reproduced [INFERENCE from `agent_projection.cpp:163-175,259-275`].
6. **Bounded selected-USB smoke:** one real status/order change reaches new ACKed revision, old slot cannot focus replacement, sync disables keys, exact focus remains `PENDING → FOCUSED`. No long qualification.

## Common Pitfalls

- `events.subscribe` ACK is mistaken for a stream: current one-request client receives no pushes [VERIFIED: `herdr.py:25-30,39-77`]. Prove persistent intake or use explicit polling/stale state.
- Partial close/status event becomes a replacement identity: freeze old identity, refresh complete rows [VERIFIED: prior `02-RESEARCH.md:280-290`; `projection.py:205-229`].
- Event storms churn revisions/redraws: coalesce and compare normalized payloads [INFERENCE grounded in `projection.py:164-193` and direct rendering].
- `request_v2` silently drops a focus intent while waiting for ACK [VERIFIED: `usb.py:116-152`]. Queue boundedly or fence input.
- Buffering commits early and mixes pixels/bindings: retain `SYNC` and one post-flush commit [VERIFIED: `agent_projection.cpp:152-190`].
- Old feedback deadlines survive a new generation: clear pending IDs, bindings, and deadlines [INFERENCE from `agent_projection.cpp:163-175,259-275`].
- Host ready is set before device ACK: every refresh must use `_publish_snapshot` checks [VERIFIED: `bridge.py:562-573`].
- Buffer exceeds RAM or violates sequential panel hardware: measure selected build/device; native tests cannot prove visual flicker [VERIFIED: `board_adapter.cpp:81-89`; [INFERENCE] for unmeasured RAM/API].
