<decisions>
## Implementation Decisions

### Existing Phase Plans Are Authoritative
- Typed Herdr lifecycle events are invalidation signals only; complete authoritative reads supply all displayed identity, rank, order, and status.
- Persistent push is admitted only after the same connection returns a correlated subscribe ACK followed by a bounded typed lifecycle frame; otherwise use bounded complete-snapshot polling.
- Refresh bursts coalesce to one complete publication plus at most one follow-up; normalized-equivalent state does not advance revision or redraw.
- Readiness and focus remain fenced until the exact current snapshot receives an accepted ACK; source, session, ACK, and refresh failures publish stale/offline state and fail closed.
- Same-session focus frames interleaved with snapshot ACK waiting use a fixed-capacity queue, are revalidated against their original generation, and are cleared on reconnect or source transition.
- Firmware composes each panel in one reused 128x128 RGB565 buffer and flushes panels sequentially; bindings activate only after all three panel flushes succeed.
- Generation replacement clears pending focus and feedback deadlines; composition/display failure rejects the snapshot and leaves the device synchronized/disabled.
- The bounded selected-device smoke is the only physical check for this phase; do not rerun long Phase 1 qualification or Phase 4 recovery tours.

### the agent's Discretion
- Preserve existing file-local APIs, test fixtures, protocol fields, and repository conventions while implementing the approved plan details.
- Apply only correctness fixes directly required by the three existing plans; do not expand scope into Phase 3 or Phase 4.

</decisions>
