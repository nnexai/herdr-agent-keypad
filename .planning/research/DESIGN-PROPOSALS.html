DESIGN PROPOSALS / HERDR AGENT KEYPAD
4 directions · built from the onboarding packet · 17 AUG 2026

Four languages for 128 pixels of agent attention.

Each proposal below is a complete system: agent-tile layout with exact device-pixel geometry, every agent / feedback / health state, a Codex usage composition for panel 4, an LED grammar over the real 14-pixel strip, and motion rules. All four respect the same invariants — inbox order authority, direct-press focus-only keys, truthful absence, and no color-alone semantics. Mockups are drawn at 2× (1 device px = 2 css px).

A · SIGNAL EDGEThe left rail carries state. Text stays quiet; the edge pattern + glyph do the talking. LEDs echo the rail. B · LEDGERA typographic inbox row. Monochrome-first, densest information, color only as an underline. LEDs stay dark until something is urgent. C · BEACONReadable from across the desk. Huge glyph, tinted field, one-line title. Full LED choreography mirrors the tiles. D · INSTRUMENTA gauge-cluster object. Ring dials for agents, dual bar gauges for usage, the accent LED row becomes a physical usage meter.

TYPE TIERS · DEVICE PX ON THE 128 GRID

Two text sizes, hard floor

T1 title / state word 10–12 px cell (8 px cap), bold · T2 meta 8 px cell (5×7 glyph) — the smallest text anywhere; nothing below it exists. At 8 px, ~15 characters fit beside margins, so every meta string is budgeted, not just ellipsized. Glyphs 24–44 px drawn primitives, never font glyphs. All coordinates are device pixels.

TRUTH RULES · APPLY TO EVERY FRAME

Absence is rendered, never faked

Null usage ≠ 0%. Provider reset time ≠ observation age. Stale data is visibly fenced before it is reusable. A failed focus never shows a success mark. Empty slots carry no key affordance. UNKNOWN and SETTLED share a color but never a glyph or edge pattern.

LED POWER POLICY · ALL DESIGNS

Restraint is a feature

Global brightness cap 45; resting states ≤ 25; at most 6 LEDs above 25 simultaneously; no persistent white; every grammar defines a dim mode at brightness 8 and an all-off state. Only BLOCKED may animate persistently, at 1.2 s period — the same period as its on-screen motion.

Stated assumptions (flagging per packet rules): ① the encoder menu may render either as a panel-4 overlay or as a full-cluster takeover — both are acceptable; mockups show the panel-4 variant, and in either case the three agent keys stay direct and non-modal; ② “since” / “age” are displayed as source text verbatim, never recomputed on-device; ③ all tile renders are compose-then-flush into the single RGB565 buffer — no design requires partial flushes or per-pixel alpha at flush time; ④ pixel truth: panels are 128 × 128 with no subpixel rendering — every spec uses whole-pixel strokes and opaque fills, the hard text floor is an 8 px cell (5×7 glyph) — nothing smaller is rendered at all, and feedback surfaces are full-width solid bands, never small translucent chips that would clip against neighboring elements.
Identity model — verified against the live API (herdr api snapshot, this machine): a workspace can host multiple agents at once (observed: two agents in one workspace, one done + one working, in different tabs). Each agent row supplies an agent type (observed: omp, copilot), workspace_id, tab_id — and tabs carry human labels (observed: main, addition) — plus terminal title and the inbox tokens. Consequence for all four designs: the discriminator line is a composite, workspace · tab (falling back to workspace · agent-type when the tab label is a bare number), so two agents from the same repository never render identical identity lines. The agent type is additionally available as a bounded label wherever a design has room for it.
DESIGN A / SIGNAL EDGE

The edge is the state. Everything else is quiet.

A 16 px colored rail on the left edge carries the entire state vocabulary through width + pattern, so the state is legible from an extreme angle and in grayscale. The tile interior is calm typography. Feedback arrives as a bottom band that never covers the title — you always know what you pressed while you learn how it went.

Rule set A: only the five backlight pixels (1, 4, 7, 10, 13) ever light in resting state; the nine accents stay off — the light appears to come from the key itself, giving a 1:1 physical mapping with zero ambiguity. Brightness ladder: BLOCKED 40 pulsing · UNSEEN 30 steady · WORKING 18 steady · IDLE 8 steady · SETTLED/UNKNOWN/EMPTY off. Usage backlight L10: cyan when current, amber at ≥ 75 %, red at limit, off when unavailable. Encoder backlight L13 lights only while the menu is open. Press feedback: pressed key's backlight snaps to cyan 45 during PENDING, flashes lime twice on FOCUSED, red twice on failure, then returns. OFFLINE/STALE: all five backlights breathe dim red at 8 in unison — the object itself says "don't trust me". Dim mode scales everything to brightness ≤ 8; all-off is one mask write.
WHY THIS DIRECTION

Angle-proof, grayscale-proof, cheap

Rail width/pattern reads at extreme viewing angles where glyphs blur. State changes redraw one 16×128 strip + one word — friendly to the compose-then-flush budget. The bottom feedback band keeps the answer to “what did I press?” on screen for the whole feedback lifetime.

RISKS

Rail literacy is learned

Width/pattern coding needs a day of familiarity (the state word is always present as backup). The 16 px rail costs ~12 % of horizontal title space. Blocked’s crawling dashes must stay subtle or the leftmost tile dominates the desk.

DESIGN B / LEDGER

A typographic inbox row, carved into glass.

The densest of the four: the tile is a print-quality ledger entry. Monochrome-first — the whole hierarchy works in white/gray; the only color on a resting tile is a 5 px underline beneath the state word. Except BLOCKED, which inverts into a solid rose band, making it the single loud thing an otherwise silent instrument can do. Feedback reuses exactly that grammar: it takes over the header band — full-width, opaque, 9 px bold ink-dark caps on a solid fill — never a corner chip, which at native 128 px would be a ~6 px translucent scrap clipping into the header.

LED grammar B · “dark until it matters” — one meaning per light event

Rule set B: the strip is an exception channel. Lit means “act” — nothing lights for WORKING/IDLE/SETTLED. Exactly four events may light LEDs: ① BLOCKED → that key's backlight breathes rose at 30; ② UNSEEN → that key's backlight steady blue at 20; ③ usage limit reached → L10 steady red 25; ④ source not current (stale/offline/unavailable) → the four above-key accents (0, 3, 6, 9) hold dim red 10 while backlights keep agent meaning. Press feedback is display-only — no LED role, no competing dashboard. Unlit is the healthy norm, so a dark keypad reads as "all quiet", and any light is a guaranteed call to action. Dim mode halves all values; all-off unchanged.
WHY THIS DIRECTION

Highest information density, calmest object

Ledger shows age + since + slot position + optional seq/revision diagnostics — the most packet vocabulary of any direction. Monochrome-first means brightness, hue drift, and panel variance can’t corrupt meaning. The LED silence policy makes it the best fit for a desk you look at all day.

RISKS

Not glanceable at distance

Two-row titles at the 8 px cap still demand close range; across-the-room legibility is delegated entirely to the BLOCKED inversion and the LED exception channel. If the user wants ambient state awareness (design C’s promise), this is the wrong direction.

DESIGN C / BEACON

Readable from across the desk. Loud on purpose.

The inverse bet of Ledger: the keypad is an ambient signal object first, a text surface second. A giant 44 px state glyph sits on a state-tinted radial field; the title is one small line at the bottom. You learn what deserves attention before you're close enough to read a word — and the LEDs run a full choreography that extends each tile’s field into physical light.

Rule set C: each key owns a 3-LED halo — its backlight plus the above-key accent and the following inter-key accent (K1: 0-1-2 · K2: 3-4-5 · K3: 6-7-8 · usage: 9-10-11) — painted in the tile's state hue with the backlight brightest (halo at 40/60 % of it). The tile field visually continues off-glass into light. Brightness ladder: blocked 38 breathing (whole halo in phase with the on-screen field) · unseen 28 · working 16 · idle 8 · settled/unknown/empty off. Usage halo: cyan current, amber ≥ 75 %, red at limit, off unavailable. Press: pressed halo sweeps 0→1→2 cyan during PENDING, solid lime blink ×2 on FOCUSED, red ×2 on failure. OFFLINE: all halos off, encoder pair 12-13 breathes red 10 — one dedicated health zone instead of poisoning agent zones. Menu open: 12-13 steady amber 20. Hard cap: whole-strip power budget enforced by scaling all values when > 6 LEDs exceed 25.
WHY THIS DIRECTION

The only across-the-room design

Glyph + tinted field + LED halo give three distance rings: LEDs at 4 m, glyph/field at 2 m, words at arm's length. State→tile association is instant because light physically surrounds the key you'd press. This is the direction that most exploits owning dedicated hardware.

RISKS

Brightest, least dense

Only one title line — long titles truncate hard (packet allows 64 chars; ~15 fit at the 8 px floor). Radial fields cost full-tile redraws on every state change. The LED choreography must respect the power budget; the enforcement rule is specified but needs bring-up validation.

DESIGN D / INSTRUMENT

A gauge cluster for agents. Ring dials, not tiles.

Treats the keypad as lab equipment: every panel is a circular dial in a corner-ticked bezel. State lives in the ring’s stroke style — solid, thin, dashed, double, dotted — a channel that is colorblind-safe and instantly familiar from hardware indicators. The four panels read as one instrument; the accent LED row doubles as a physical usage meter.

Rule set D: two independent instruments in one strip. Lamps — the five backlights carry per-control state exactly as in grammar A (blocked breathes 40, unseen 30, working 18, idle 8; usage L10 = health hue; encoder L13 = menu open). Meter — the four above/between accents L0-L2-L3-L6* run left→right as a physical fill gauge of the primary usage window: 0-25-50-75 % steps, cyan while normal, amber ≥ 75 %, red at limit, all four off when usage is unavailable/stale (an unlit meter is an honest broken meter). Remaining accents (5, 8, 9, 11, 12) stay permanently dark to keep the meter unambiguous. OFFLINE: lamps switch to unison dim-red breathing, meter goes dark. *exact meter indices are the first four top-row accents; final pick after physical sighting since inter-key accents sit between meter stops.
WHY THIS DIRECTION

One dialect for all four panels

Agents, usage, failures, and the menu all speak ring/gauge/bezel — lowest learning cost across surfaces. The bezel-tick health channel is unique: source trouble changes the frame, not the content, so stale data remains readable while being unmistakably fenced. The LED meter answers “how much Codex is left?” without even looking at a screen.

RISKS

Ring stroke rendering + meter literacy

Dashed/double/dotted circles need clean arc primitives at 128 px (LovyanGFX arcs can alias; needs a bring-up test). The 4-step LED meter is coarse (25 % resolution) and its physical stop positions interleave with backlights — final indices need on-device sighting.

05 / MOTION & TRANSITIONS

Motion is a budget, spent on meaning.

RECOMMENDATION

Ship B’s truth-density on A’s skeleton, borrow D’s meter

If one direction must be chosen: Signal Edge (A) is the safest primary — cheapest to render flicker-free, angle-proof, and its feedback band is the clearest press story. The strongest hybrid: A’s tile skeleton + B’s header row (disc · age) and slot dots + D’s LED usage meter, keeping B’s “dark until it matters” policy for the agent backlights. Every element in this page is specified in device pixels and HSV values, so any mix is directly implementable.

WHAT TO VALIDATE ON HARDWARE FIRST

Five bring-up checks
