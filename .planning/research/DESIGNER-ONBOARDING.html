01 / THE JOB

Make the inbox legible before the user opens it.

The keypad is a companion surface for a live Herdr inbox. It should tell the user which agents currently deserve attention, make their state recognizable at a glance, and let one physical press move the user to the exact pane represented on the tile.

CORE LOOP

See → choose → arrive

Three fixed agent surfaces show the installed inbox’s current top entries. A key press requests focus only. The actual conversation remains in Herdr.

TRUTHFULNESS

Unknown is a state

Stale, unavailable, offline, and missing values must not masquerade as current data. Null usage is not zero. A failed focus is not success.

BOUNDARY

Hardware, not a tiny app

There is no need to reproduce Herdr’s conversation UI. The keypad is a glanceable instrument: sparse, physical, immediate, and readable at 128 pixels.

Design stance: You are free to reshape the visual language, hierarchy, typography, icons, motion, color relationships, and LED grammar. You are not free to change inbox order authority, direct-key selection, focus-only semantics, or the host credential boundary.
02 / THE OBJECT

Know the canvas before drawing on it.

The delivered object is a LILYGO T-Keyboard-S3 Pro host board: an ESP32-S3 display/keyboard device with a co-processor that multiplexes the panels, reads the keys, and drives the LEDs.

PIXEL PHYSICS

One panel at a time

All four panels share SPI. The board adapter selects one panel through the STM32. Multi-panel simultaneous selection is unreliable; rendering flushes sequentially.

BOUNDS

16-bit RGB565

The current product renderer uses one reusable 128 × 128 RGB565 composition buffer, preferred in PSRAM. A complete image is composed, then pushed once.

READABILITY

Square, dense, close-range

Current rendering uses a 4 px inset and small text. Design for short labels, strong hierarchy, icon + text redundancy, and no reliance on color alone.

Physical mapping note: firmware logic currently treats agent slot 0/1/2 as display 1/2/3 and key 0/1/2. The fourth display/key pair is reserved for the future usage surface. In the official top-side product view, the four key wells run in one row and the rotary encoder occupies the right-hand fifth position with no display of its own. The 14-pixel strip alternates above-control accents, inter-control accents, and one backlight pixel beneath each of the four keys plus the encoder.
03 / THE SOURCE, BEFORE THE BRIDGE

Herdr exposes more than the keypad currently shows.

This is the direct public Herdr vocabulary. The bridge deliberately reduces it to a safe device projection, but a designer should understand the richer source so proposed visuals do not accidentally confuse source facts, inbox metadata, and device feedback.

Important distinction: everything in this section is available from Herdr’s public API or the installed herdr-agent-inbox metadata projection. It is not a promise that every field is present, fresh, or safe to put on a 128 px display.

Installed inbox metadata tokens

rank

Attention tier

0 blocked · 1 done/unread · 2 working · 3 idle · 4 unknown · 5 settled.

title

Inbox title

Derived from the agent’s native title or a configured prompt-based title strategy. The daemon defaults to the first real user prompt when no native title exists; optional summarization may be configured.

age / since

Time context

age is session running time. since is time in the current state. These are useful glance cues, but they are source text, not a device clock contract.

flag

Attention marker

⚑ means settled. ● means marked unread. Missing flag means no explicit flag.

workspace tokens

Aggregate context

Workspace metadata can include agents (per-status counts such as !1 ▸2 ✓1 ⚑1) and busy (longest working stint).

sort contract

Why order changes

The inbox sorts literal rank ascending, then state_change_seq descending. A live state change can move an entry between physical tiles.

04 / THE AGENT TILES

Three slots. One authority.

The host reads the public Herdr API and the installed inbox projection. It does not invent a priority model. The device receives three normalized entries, already ordered and bounded.

ORDERING — VERIFIED

Rank first, sequence second

Each `agent.list` row must carry the installed inbox’s literal rank token. Rows sort ascending by rank, then descending by `state_change_seq`. The first three become slots 0–2. Missing rank makes the source unavailable rather than triggering a local guess.

CONTENT — BOUNDED

What can reach a tile

Title: up to 64 ASCII characters, with fallback from title token / terminal title / agent name. Discriminator: up to 32 ASCII characters, usually workspace label or repository basename. Long display strings are ellipsized.

Payload fieldMeaning for designWhat not to do
slotFixed position 0, 1, or 2. It is a physical location, not a priority value.Do not show a ranking number unless it helps the user understand location.
titleHuman-facing agent title; bounded ASCII, possibly truncated.Do not assume it is unique or stable forever.
discriminatorWorkspace / repository cue, such as lilygo-t3.Do not expose host paths or raw workspace internals.
stateOne of empty, working, idle, blocked, finished, settled, unknown.Do not reorder or reinterpret state priority on the device.
source revisionOpaque identity freshness for exact focus correlation.It is not a user-facing progress counter by default.
pane / terminal / session identityExact target binding; invisible implementation detail unless a bounded diagnostic view needs it.Never display raw identifiers as primary UI.
Empty slots are real states: the host always sends exactly three agent records. An empty slot is explicit, with no actionable identity. A designer can make it quiet, useful, or invitation-like, but it must never look focusable.
05 / STATE LANGUAGE

State is information, not decoration.

The current implementation has a state vocabulary and a color starting point. Treat this as a semantic contract plus a visual baseline—not as a final art direction.

BLOCKED

Inbox rank 0. The agent is blocked and deserves explicit attention.

Current cue: rose / cross geometry

UNSEEN

Herdr’s finished rank maps to the product label UNSEEN. This is a visible attention cue, not a new lifecycle.

Current cue: blue / filled dot

WORKING

The agent is actively working.

Current cue: amber / play-like triangle

IDLE

The agent is idle. It may still be a valid focus target.

Current cue: green / ring

SETTLED

Herdr’s settled state is shown distinctly; the keypad does not create or settle it.

Current cue: violet / corner mark

UNKNOWN

Unknown is honest uncertainty in the source state.

Current cue: violet / ring fallback

Source health states

CURRENT

Complete authoritative data is available and the three tiles can be actionable.

EMPTY

The authoritative source has no entries. Render explicit empty tiles, not stale ghosts.

STALE

Previous data exists but is no longer safe to call current. Focus must be fenced.

UNAVAILABLE

The source is incompatible, incomplete, or failed to supply a valid projection.

OFFLINE

Host, Herdr, or transport connectivity is not available. Distinguish from stale cache.

Design opportunity: build a visual grammar where every state survives grayscale, low brightness, and glance distance. Color, label, icon geometry, edge treatment, and motion can reinforce one another.

WHAT THE CODE CURRENTLY DOES

Stable information skeleton

Every occupied tile has a title, discriminator, state label, central geometry, and a bottom action hint. Empty tiles say NO AGENT. Sync uses a full-panel SYNC / UPDATING veil. Feedback temporarily overrides the state label with PENDING, FOCUSED, or a failure state.

WHAT YOU MAY REPLACE

Almost everything visual

You can replace the rail, glyphs, copy, type scale, footer, state placement, title treatment, and transition behavior. Preserve only the truthful meanings, the fixed physical slots, and the ability to understand the state without color alone.

AVAILABLE BUT NOT PRODUCT UI

Temporary bring-up screens

The firmware also contains a physical qualification renderer for the whole board: WAIT, MAP, PRESS, TURN CW, TURN CCW, ENC CLICK, BRIGHTNESS, PAIR, PASS, FAIL, and LINK LOST. These are implementation assets and physical-test vocabulary, not an accepted product information architecture. They may be useful reference material for diagnostics or recovery design.

07 / PRESS FEEDBACK

A press is a tiny state machine.

A key press never means “mark done.” It means “request focus for the exact pane represented here.” The device gives immediate local feedback, then accepts the host result only when identity and generation match.

PENDING

REJECTED

not a retry affordance

Known operation failure.

not a success state
DISABLED

Syncing, empty, or unavailable.

key must not act
ALLOWED

Focus-only

The only host write is agent.focus for the exact displayed pane. Herdr may naturally update seen/manual-unread state as a side effect.

FORBIDDEN

No hidden triage

No settle, dismiss, acknowledge, clear, reply, approve, or arbitrary command. No optimistic success. No replay after reconnect.

08 / THE LIGHT FIELD

Fourteen lights, no assigned language yet.

The board exposes 14 WS2812C RGB LEDs driven by the STM32 co-processor. The API supports HSV hue 0–360, saturation 0–100, brightness 0–100, and a 14-bit LED mask.

WHAT EXISTS

Hardware and control

Per-LED selection is available. Firmware has a board adapter seam for setLeds(hue, saturation, brightness, ledMask). The user-facing mask convention is bit 0 = LED1 through bit 13 = LED14. The verified bring-up utility can switch all LEDs off, all on, or address individual LEDs.

09 / USAGE AND MENU SURFACES

The fourth panel is a promise, not a finished screen.

Phase 3 owns the Codex usage tile and encoder menu. The requirements are known; the layout, interaction choreography, typography, and visual hierarchy are open for you to propose.

planned

Panel 4 · Codex usage

Dedicated, read-only surface. Show both primary and secondary subscription-window percentages whenever the installed account supplies them; nearest relevant reset; reached-limit state; and observation age.

Never infer: missing/null is unavailable, not 0%. A provider reset timestamp is not observation freshness. API-key auth is not ChatGPT subscription quota.

planned

Encoder menu

Encoder click opens/closes a secondary menu. Agent keys remain direct and non-modal while the menu is open. Menu candidates: link health, Herdr health, Codex health, last full sync, last Codex observation, bounded troubleshooting IDs, firmware/protocol versions, and brightness.

Brightness: should persist independently of inbox bindings, order, identity, and focus semantics.

10 / DESIGN SPACE

Choose a language. Keep the invariants.

The current screen is a functional reference, not a mandate. The source exposes more information than the device currently uses; the visual system can be radically different if it remains legible, truthful, and fast.

AVAILABLE MATERIAL

Hierarchy

Title-first, state-first, urgency-first, edge-first, icon-first, or a spatial composition that makes the physical key relationship obvious.

AVAILABLE MATERIAL

Expression

Color palette, icon geometry, type scale, density, borders, texture, animation, LED choreography, and the relationship between display and light.

AVAILABLE MATERIAL

Modes

Calm idle, attention, transition, usage, diagnostics, and recovery surfaces can share one language or become deliberately distinct.

DO NOT CHANGE

Product invariants

A

Direct agent keys. The three agent choices must remain one physical press away, even when the encoder menu is open.

B

Installed order. The keypad mirrors Herdr’s inbox order; it does not invent or reprioritize the lifecycle.

C

Focus only. A press changes pane focus. It must not settle, dismiss, reply, approve, or acknowledge.

D

Truthful absence. Current, stale, unavailable, offline, and unknown must be distinguishable.
